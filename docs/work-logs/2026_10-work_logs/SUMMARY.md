## Patterns and decisions

- **Prove the actual consumer.** A source function, host fixture or isolated helper did not by itself prove the combined installed flow. Actual writer/reader pairing, current source identities and visible readiness supplied the stronger evidence.
- **Preserve failure channels.** Failed setup, incomplete presentation, failed cleanup and successful producer work required different dispositions. October's #597 producer-ownership correction is a durable example.
- **Keep current plans current.** Stale live guidance could still point at an older accepted image or describe already completed preparation. D-WORKFLOW-139 requires the milestone body and open titles to carry actual current/next work. The October 15 propagation addendum records completed readback; it is not still pending.
- **Keep authority narrow.** Reboot, cloud mutation, device observation, fixture execution and publication remain distinct actions. The guarded-swap and rename futros already separated prepared source from actual runtime/privilege behavior.
- **Retain compatibility deliberately.** D-WORKFLOW-144 fixed the project name; D-CLOUD-175 fixed normal cloud setup; D-WORKFLOW-161 selected the October stable foundation for that period. November's later foundation choice does not rewrite October history.
