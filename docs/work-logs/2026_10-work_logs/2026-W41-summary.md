## Friction and changes to the process

A successful script return repeatedly proved narrower than acceptance: fixtures
misread outcome codes, compositor behavior differed on software rendering, and
old configuration writers could undo a temporary maintenance mask. The fixes
used actual rendered frames, current-boot identities, source-bound installed
bytes and explicit failure/recovery controls. Original failures stayed visible.

Audit work paused after a checkpoint when it could have continued. The resulting
continuity work clarified watched long-running review and result delivery;
a saved research state is not an instruction to stop an authorized audit.
Capacity pressure likewise prompted exact dependency reports, guarded cleanup
and an ongoing retention task. Retaining compact evidence is separate from
retaining superseded VM disks, firmware or build trees.
