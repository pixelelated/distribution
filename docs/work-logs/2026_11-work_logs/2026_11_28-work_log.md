## 04:25 UTC — tools/source-check: a build's unfetchable sources found before the build, its positive on the 03:49 cache state (#1509)

`tools/source-check --commit <rev> --device <D>` reads in two to five minutes what the H700 build took an hour to find out. For each arch it:
- makes the plan in the pinned build container, as `config/multithread` does (`--build image`, or `--build arm` for the 32-bit half);
- reads each recipe's source for that device and arch;
- judges the source against the cache by `get_archive`'s and `get_git`'s own rules;
- asks the URL and the mirror for anything it would have to fetch. Exit 0, 1, or 2 when it cannot run.

**Why the container.** The host has no `xmlstarlet`, so `config/functions` leaves `SUBDEVICES` empty there. On the host, H700's plan lost `u-boot-DDR3`, `u-boot-DDR4`, `atf`, the suspend stub, and `pyelftools`/`swig` for the host. In the container, the plans equal the running H700 build's exactly: aarch64 666 of 666 tasks, arm 258 of 258 (`--keep-plans`). ES's recipe refuses any root but the build's in `configure_package`, so it stands in the plan by its declared dependencies, and its `file://` source is listed as supplied.

**The guard's positive (2026-11-28 04:12 UTC).** The command was `tools/source-check --commit 6169621a4b --device H700 --arch aarch64 --packages duckstation-sa --sources <a fixture holding the 0-byte file the 03:49 run left>`.
