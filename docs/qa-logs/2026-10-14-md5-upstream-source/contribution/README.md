# MD5 input-alignment correction

`md5-alignment.patch` changes only `utils/md5.c` in libretro/libretro-common.
Base: a3194c18ba65ef89734e1898a2f61403c255d368 (master observed2026-10-14).
It copies each input word into a local `uint32_t` with `memcpy`, removing the
alignment/effective-type assumption on the i386/x86_64/vax path. The generic
little-endian byte assembly, public API, digest rounds, and license are unchanged.
No alignment sanitizer suppression or compiler aliasing workaround is used.
Generated machine code and performance have not been measured.

The standalone control emits264 rows: eight offsets, eleven lengths around
padding/block boundaries, and three update splits. Inputs are generated bytes;
no game, account, file input, or network is used by the C control. The public
control is unchanged from the downstream tested version. Upstream has replaced
its `MD5_u32plus` typedef with `uint32_t`; the reproduction compiler command maps
that old name with `-DMD5_u32plus=uint32_t`. This is a test-source compatibility
mapping; the actual upstream patch uses the existing `uint32_t` type directly.

`upstream/` contains only the pinned original MD5 implementation and its five
project headers. All source/license/author notices remain unchanged. `source.json`
binds these files and the patched output. There are no third-party build-system,
libcheck, frontend, or external library dependencies beyond a C toolchain with
ASan/UBSan, the host C library, Bash, Python3.9+, GNU timeout, patch, and sha256sum.

**Prepared procedure, not yet run against this upstream snapshot.** On a
newly allocated x86_64 Linux test host, supply a NEW absolute output directory
and the absolute path to GCC or Clang (never a compiler command with arguments):

```sh
bash /absolute/path/to/contribution/reproduce.sh \
  /absolute/path/to/new-md5-run /absolute/path/to/gcc
```

The script verifies this bundle, stages only two private MD5 source copies,
applies the patch to one, verifies its exact output hash, and builds both with
`-O1 -g -fstrict-aliasing -fsanitize=address,undefined
-fno-sanitize-recover=all -fno-omit-frame-pointer`. It changes no checkout.
Each compile has60seconds, each target15seconds, with5seconds to force termination;
patching has10seconds. Core dumps are disabled, the Bash file limit is8MiB,
and the script preserves every output and command/timeout-wrapper exit.
Timeout124/137 or any unexpected exit is failure, never the expected defect.
Compiler/runtime choice and host resource admission belong to the caller.
No automatic cleanup removes failure evidence; retire the fresh output after
consuming it. Record the selected compiler/version and original wrapper exit.

Acceptance requires unpatched exit1 with an MD5-source misaligned-load diagnostic,
then patched exit0, empty sanitizer stderr, and all264 rows matching independent
Python hashlib digests in exact order. Missing/duplicate/reordered/changed rows
fail. `comparison.json` is written only when those conditions pass. A machine
where the unpatched defect is not reproduced yields an inconclusive failure,
not a claim of success. There is no 32-bit, ARM, vax, big-endian, Apple, performance,
or full upstream suite claim here.

Downstream validation is separate: the same memcpy implementation (old typedef
spelling) passed target-built ES-integrated ASan/UBSan controls in an x86_64 Linux
VM:264 independent digest rows for each of two repaired library compositions,
plus synthetic GameCube/Saturn ISO/CUE wrapper repetitions and Wii-helper checks.
That validates the downstream integration, not this upstream snapshot or script.
An earlier pristine downstream baseline's alignment UB remains the failure
control; its later repaired comparison does not erase it.
