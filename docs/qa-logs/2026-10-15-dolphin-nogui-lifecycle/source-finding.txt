Source/Core/DolphinNoGUI/MainNoGUI.cpp:280-288 initializes UICommon/controllers
and installs their shutdown guard. It never initializes AchievementManager.
UICommon/UICommon.cpp:126-159 initializes and destroys configuration, logging,
video settings and related components, but not achievements. Desktop Qt calls
AchievementManager::Init in MainWindow.cpp:270 and Shutdown in its destructor
at349. Android has its own initialization calls (AchievementAdapter.cpp:18 and
MainAndroid.cpp:524); this is a NoGUI omission, not a universal non-Qt defect.

Core/AchievementManager.cpp:64-99 creates rc_client only when RA is enabled,
sets the configured HostUrl at73-75, sets events/hardcore policy, starts its
queues, and starts token login at94-95. Without that call, the normal game-load
path (Core/Boot/Boot.cpp:527) reaches LoadGame, which returns with an
'uninitialized client' error at AchievementManager.cpp:162-166. The new #584
launcher routing can write the correct HostUrl while the player never reads it.
This is independent of the repaired ES RVZ reader and proxy RVZ hashing.

Proposed production content

018-nogui-achievements-lifecycle.patch adds only three guarded sections to
MainNoGUI.cpp: include AchievementManager.h, call Init(wsi.render_window)
after signal-handler installation and before BootCore, and pair it with a dedicated scope guard. Normal exit calls that guard before
s_platform.reset, preserving the native window for RAIntegration teardown; the
existing UICommon teardown order stays unchanged.
It does not move Qt/Android ownership or initialize a second client there.
recipe-comment.patch removes the false assumption that compiling Core alone
makes achievements frontend-independent. Patch018 avoids current ROCKNIX's
already used017 (Qt window pixel ratio).

Startup/teardown trace

* Argument/platform rejection before UICommon creates no client.
* The save-state-without-game rejection occurs before achievement Init and
  before its dedicated guard; only the existing UICommon guard runs.
* Successful normal startup creates the client after config has loaded and
  before BootCore can call LoadGame. The existing core path supplies game load,
  frame work and close; no Qt event loop is required for the manager's HTTP queue.
* BootCore false return runs the achievement guard, then UICommon cleanup,
  even though main returns1.
* Normal signal/platform exit first executes Core::Stop and Core::Shutdown;
  achievement_manager_guard.Exit() shuts achievements down before the platform
  window is destroyed. The later guard destructor is a no-op; UICommon cleanup
  retains its existing final position.
* Manager Shutdown (796-810) calls CloseGame, joins m_queue, removes its config
  callback, destroys rc_client and preserves credentials (it does not Logout).
  CloseGame synchronously cancels both pending queues and clears game/system
  state. The existing image worker is cancelled here and joined by its
  WorkQueueThread destructor at process-static teardown; this patch deliberately
  uses the existing public lifecycle rather than changing shared manager code.
  As in upstream Qt, fatal signals/forced process termination bypass C++ guards.
