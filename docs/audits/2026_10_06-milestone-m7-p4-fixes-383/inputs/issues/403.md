## Qualification input defect

The full host regression runner discovers busybox and rclone only under
build.ROCKNIX-* directories. The frozen Rasteratops candidate uses
build.RASTERATOPS-GENERIC_X64.x86_64, so a current source test silently consumes
an older warm image's executables. The current old x64 BusyBox hash is
215ea66553232151ff62626fd3e0345de71fd1d313ee29a3d9ab623a7a95e812;
the candidate hash is
5e8a914240e227daa06eb3dbc2f97e3198cd9f9f6cd6d099bf104be9792dee2f.
Earlier host-source results remain historical; they are not exact candidate
binary qualification. Guest runtime results and retained artifacts are unaffected.

Can this be done on the VM? The defect is host input selection. Actual executable
selection controls can verify it without a guest, and the full suite must then
consume the candidate's image-system directory, with path/hash evidence.

## Acceptance

- [x] Support an explicit image-system root for both BusyBox and rclone, fail closed if that named input is absent/unusable, and discover branded roots when no override is named.
- [x] Actual selection controls fail against the old logic and pass with the correction, including a spaced path and an invalid explicit root.
- [x] Full host regression runs with the candidate executable hashes retained; correct any failures and record exact source scope.

Refs #383, #401. No change to product bytes or existing VM receipts is implied.
