## Intended behavior

A root-owned helper can recycle only the already-active regular `/swap.img`. It accepts no caller-selected paths, commands, thresholds or environment overrides. Refuse unsafe ownership/modes, unexpected swap configuration, insufficient available RAM, simultaneous reclamation and active build/VM work. Preserve activation/priority, attempt reactivation after failures/signals, and verify actual `/proc/swaps` state before reporting success. Healthy swap is a no-op.

Expose it through an explicit `tools/build-preflight --reclaim-swap` option. A one-time reviewed installer grants max only the exact helper action through a root-owned, validated sudoers entry; no general passwordless sudo. The owner completed the reviewed bootstrap; only the fixed noninteractive helper action is granted.

## Can this be done on the VM?

Yes. Guard logic, exact command selection and failure recovery can be exercised with isolated host fixtures and simulated swap commands, without touching host swap. Installation/permission readbacks on serval establish the host boundary; an actual recycle must wait until no build/VM work is active. Do not claim a simulated reset is a real kernel reset or weaken guards for testing.
