# M7.P2: pre-push — merging next into a feature branch makes the hook re-judge next's published history, so the branch cannot be pushed

Source: https://github.com/pixelelated/distribution/issues/371
Updated: 2026-10-04T03:09:58Z

## What was found

While bringing the session worktree's branch level with `next` for the handoff (#368), `git push origin feature/conflict-resolution` was refused by `.githooks/pre-push`: "a commit in this push adds a credential-shaped line" and "a listed word", naming `46d7cd00b5`, `d047546616` and `06846da9ef`. All three are already published: `git branch -r --contains` lists `origin/next` (and `origin/feature/cloud-epic`) for each. The push carried them only because `next` was merged into the branch (`bbb2c635fe`).

## Why

For a branch that already exists on the remote, the hook scans `<remote sha>..<local sha>`; it excludes what other remote refs already hold only for a new branch (`git rev-list ... --not --remotes`, line 203). So merging `next` into any feature branch makes the hook re-judge `next`'s published history, and a branch can no longer be brought level with `next` and pushed. Nothing was bypassed: the merge stays local.
