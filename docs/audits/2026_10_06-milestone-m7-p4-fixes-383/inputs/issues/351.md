## Earlier scoped record

Four observations from the maintainer while pairing Dropbox on the Retroid Pocket Nova through the phone keyboard page (2026-09-30), one section each (as #85 did).

## 1. The Close control is where a thumb lands

> One issue I just ran into is that the close page right above the pointer makes it easy to accidentally click. […] With the close page, we might want to maybe move this either row below, or, if possible, maybe have it show a modal in style saying "Are you sure?" so someone doesn't accidentally click it like I just did.

**Today** (`cloud_oauth` at `224b73ea54`): the Close page key is a `.keys` row of its own at `:992-994`, directly above `<h2>Pointer</h2>` and the drag pad (`:996-997`); it sends Escape, which quits the sign-in window (`:989-991`, `cloud-signin-window.c:499-500`), and a sign-in closed that way is `CLOSED_EARLY` (`:578`): the player starts the sign-in again from the handheld.

## 2. The text above the field is too tight before the keyboard connects

> Also, before the keyboard is connected, the text between the keyboard for Dropbox and the text input field is too tightly spaced.

**Today**: the state line is `<div id=state class=note>Checking…</div>` (`:965`) with no margin of its own, between an `h1` whose bottom margin is `.25rem` (`STYLE`, `:625`) and the input, which has none (`:631`).

## 3. The "Trust this device" picture is tiny

> Also, the image we show for "Trust this device" is tiny. I can send a picture if that helps.

**Today**: which surface shows it is not yet read; the picture the maintainer offered decides it (Dropbox's own device-approval page in the fullscreen WebKit window, or a page of ours).

## 4. The success screen has no styling

> Additionally, the success screen we show doesn't have any styling. We should give it a bit of styling to make it not look a lot like a 404 page or something incredibly basic.

**Today**: when the sign-in lands, the window replaces the provider's page with `FINISHING_PAGE`, a one-line `data:` document reading `Finishing up…` in a system font on a dark background with none of the shared style (`cloud-signin-window.c:423-427`); before the done file lands, rclone's own callback page (`127.0.0.1:53682`) may show for a moment. The phone's `Connected` page carries the shared style (`cloud_oauth:738-746`).

## 3, read from the maintainer's photo (2026-10-01)

The screen is **Dropbox's own "Trust this device?" page** rendered in the fork's fullscreen sign-in window (the help bar under it is ours: `A select  B back  X keyboard  Y next  L1/R1 scroll  SELECT + START to exit`). The tiny image is Dropbox's monitor icon in its desktop layout, which it serves because the window reports a desktop-sized viewport; Dropbox's cookie banner overlaps the bottom left. Nothing in that page is ours to restyle; the lever is the window's: `webkit_web_view_set_zoom_level` keyed on the panel width, or a phone user agent so the provider serves its touch layout.
