# M7.P3: Keep failed bucket listings distinct from an absent saves folder

Source: https://github.com/pixelelated/distribution/issues/377
Updated: 2026-10-04T00:08:09Z

## Found during readiness review #375

Medium: an unreadable bucket parent becomes “folder absent” before backup. At distro `b2378d9c33`, `cloud_backup:819–825` pipes `rclone lsf --dirs-only` into grep; the guard at `:1677–1685` turns any false `bucket_dir_listed` answer into status 3. With a synthetic successful `lsd`, a bucket backend, and `lsf` failing with status 5, the exact production helper/control block returns `>>> offer create-saves-folder|/ROCKNIX/Saves` and exit 0.

D-CLOUD-172 distinguishes absence from a listing that cannot answer: the latter leaves backup behavior as it was. A failed provider read is not evidence the folder is absent. The `cloud_restore` sibling helper needs the same classification review; its behavior has not been asserted as independently reproduced here.

Already written: this path skips the backup and offers folder creation without proving absence. The probe does not show cloud deletion or data loss; existing saves must be preserved while the error remains retriable.

Related: #363, #364, #365 and cloud epic #354. Evidence and reproduction: `docs/audits/2026_10_02-milestone-375-rasteratops-0-0-1/evidence/bucket-unknown-probe.{sh,log}`. Retrospective: `docs/retros/2026-10-02-cloud-runs-95-101.md`. Both approved Fable passes now verify this finding; the primary checked the source and host predicate. Formal report: audit #375.

## Can this be done on the VM?

Yes — host production-script fault injection and GENERIC_X64 with the synthetic S3 QA backend distinguish successful empty listings from failed reads. No real provider account or physical device is required.

## Independent review correction (2026-10-02)

Fable refutation narrows the backup exposure: the supplied S3 QA configuration prefixes paths with a bucket, while superseded_saves_setting compares the complete value with /GAMES or /ROCKNIX/Saves. Use a reachable synthetic bucket-shaped fixture for that guard, and S3 for cloud_restore:1676, which has no superseded-name gate. The restore parent-listing failure can also become an absence offer. Audit the features-query failure classification alongside these helpers; a failed features read must not be treated as verified backend type. No real-provider recreation or cloud deletion was demonstrated.
