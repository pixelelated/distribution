# M7.P3: Pass pixelelated identity into the EmulationStation process

Source: https://github.com/pixelelated/distribution/issues/424
Updated: 2026-10-04T23:45:41Z

Actual candidate1e6a VM frame `ui-05/artifacts/en_US-640x480/retro-achievements/01-main-menu-entry.png` reads `ROCKNIX 0.0.1 (community)`. The actual guest `/etc/os-release` has `OS_NAME="pixelelated"`, but reading only OS_NAME from the running EmulationStation process environment yields no value. `ApiSystem::getApplicationName()` reads that environment field and falls back to ROCKNIX when absent. The service launches `/usr/bin/start_es.sh` with EnvironmentFiles=/etc/profile.

This defeats the visible rename and can also select the wrong update interface because `openUpdatesSettings` gates the pixelelated manual-update branch on the same application name. Merely parsing the image's os-release file did not exercise that consumer.

Maintainer requirements: “I think I want it all lowercase: "pixelelated". as a standard. we should change the default now as well.” and “If there are issues we need to resolve first, let's get those taken care of.”

Can this be done on the VM? **Yes.** Preserve the failed identity frame/environment receipt, trace the actual launch/profile boundary, correct the missing identity export, and verify the running ES process plus main-menu/information/manual-update frames on a fresh and upgraded corrected image. No physical device or personal cloud action.

Already written: the current frozen candidate has correct immutable identity metadata but its ES child lacks OS_NAME; this is not a stored-data migration. Retain existing configured settings/cloud roots and correct the launch-time environment on subsequent boot/restart in the replacement image.
