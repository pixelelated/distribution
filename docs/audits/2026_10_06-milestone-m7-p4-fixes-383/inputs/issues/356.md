## The shape proposed

A cloud layout has a version. The cloud root carries a small marker (`/Rasteratops/.layout`, one line: `layout=2`), written by the device that creates or moves the folders; each device compares the marker with the layout its build expects and runs the numbered steps between them, one step at a time, each step a copy-verify-delete with its own one-time dialog (D-CLOUD-160's MOVE / KEEP / NOT NOW) and its own journal line. Step 1 is `/GAMES` and `/ROCKNIX` to `/Rasteratops` (#353); a later change is step 2, written once, and every device in the fleet takes it when it next checks. A device on a newer layout than the marker never writes the old shape; a device on an older build than the marker reads what it can and says so (`upgrade-and-install.md`: old code reads new data). The marker is data, not a lock: two devices racing to move is prevented by the copy-then-verify order, not by the marker.
