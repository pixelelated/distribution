## What was asked

The maintainer, 2026-10-02, on run 101's round-trip failure: *"Yeah, this should go in our friction log."*

It answers the report that had just gone up: the round-trip suite failed on run 101 not for a product fault but because its QA cloud folder is `/GAMES`, a folder this build treats as out of date, and the check written to catch stale folder names in the QA tools looks only for `GAMES/Saves`-style names, so a bare `/GAMES` passed it. The friction line in `docs/friction-log.md` names this issue as its owner.

## What exists today

- `tools/vm-qa` on run 101 (`b2378d9c33`): `round-trip | FAIL (1)`, eleven checks failed, all downstream of the saves backup. `round-trip.log` line 9 reads `SAVES_REMOTE /GAMES on the webdav endpoint`; line 16 `only 0/9 reached the bucket` (`/workspace/artifacts/rocknix-images/qa-b2378d9c33-webdav-a-20261002-0100/`).
- `tools/cloud-test-backend saves-remote` (line 806) prints `<endpoint prefix>/GAMES`, which on the WebDAV backend is `/GAMES` exactly: the first entry of `SUPERSEDED_DEFAULT_SAVES` in `cloud_migrate_layout`. `tools/cloud-round-trip` (line 344) sets the guest's `SAVES_REMOTE` to it.
- Since D-CLOUD-172 a backup does not make an absent saves folder that is an earlier default; it offers instead. The round-trip empties the QA cloud first, so its first backup lands in exactly that case, sends nothing, and the suite reads the missing files as eleven failures. The product did what D-CLOUD-161 and D-CLOUD-172 say; the fixture had been sitting in the case D-CLOUD-161 named a day earlier, and nothing failed until a script acted on it.
- The stale-name check (`tools/last-good-scripts-test`, after A5; blindspot 71's guard) greps `(ROCKNIX|GAMES)/(Saves|Backups|Content)`. A bare `/GAMES` (the first layout had no subfolder) does not match. The check carries its own copy of the earlier defaults, and that copy drifted from the one the scripts use.
- This is blindspot 71's shape a second time; the first is the friction line of 2026-10-01 16:46 (run 96). `working-principles.md`: a rule broken twice moves up a stage.

## Root cause

The list of earlier defaults has one source, `cloud_migrate_layout --superseded`, and the check and the fixture each carried a copy of their own. The fix reads the source rather than widening the pattern.

Original planning note (now completed): the step back (#365) settled the folder model used by the corrected fixture.
