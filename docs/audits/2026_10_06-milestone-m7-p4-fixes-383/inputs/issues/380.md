# M7.P3: Preserve an explicit cloud-root content choice during layout migration

Source: https://github.com/pixelelated/distribution/issues/380
Updated: 2026-10-03T23:45:06Z

## Discovered in readiness audit #375

Low; Fable blind G-10. Owner area: cloud layout / setup. Milestone: rasteratops 0.0.1.

cloud_setup and its existing #308 regression define an explicit CONTENT_REMOTE="" as the cloud root; absence of the key gets the default. Migration treats both as unset and can rewrite an explicit root to /Rasteratops/Content. The complete migration script in the isolated layout fixture reproduces this on --follow; /Mine/ROMs control is preserved. Current migration tests encode the conflicting interpretation, so green test counts do not resolve the contract.

Source: `cloud_setup:755–763; cloud_migrate_layout:114,819,883,1052`. Evidence: `docs/audits/2026_10_02-milestone-375-rasteratops-0-0-1/evidence/reviewer-layout-probe.{sh,log}`. These are isolated host reproductions, not VM qualification or evidence of deletion.

Already written: devices may have old folder pointers, settings archives and explicit content choices. Preserve existing cloud bytes and deliberate choices; a fix must not rename or delete old files merely to satisfy a fixture. Related: #353, #354, #365.

## Can this be done on the VM?

Yes — GENERIC_X64 with synthetic WebDAV/S3 fixtures and fault injection. No physical fact or personal provider account is required.

## Acceptance criteria

- [x] Regression fixtures distinguish missing CONTENT_REMOTE, explicit empty cloud root, a derived old Content folder and a named custom folder for join, follow, settle and apply; log records before/after values.
- [x] On GENERIC_X64, an explicit root holding ROMs/BIOS remains the selected location after a layout transition and the scan lists/restores the original sentinel; missing-key fixtures get the documented default.
- [x] The contradictory seeding/migration fixtures and state table agree on one representation without silently replacing a player-selected folder; existing content-root tests remain green.
