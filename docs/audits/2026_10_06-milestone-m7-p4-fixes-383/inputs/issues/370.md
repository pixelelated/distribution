# rules-check: the rule count in AGENTS.md is never read (case-sensitive match), and it is stale

Source: https://github.com/pixelelated/distribution/issues/370
Updated: 2026-10-02T21:10:37Z

## What was found

Found while giving `AGENTS.md` its pointer to the stash (#368): `AGENTS.md` says the rule files are "all 27, listed below" while `.claude/rules/` holds 29, and `tools/rules-check` passes. The index (`instruction-files.md`) says the tool proves "the counts in `CLAUDE.md` and `AGENTS.md` true".

## Why the check passed

`tools/rules-check` line 162 looks for the count with `re.findall(r'\bAll (\d+)(?: of them|,)', t)`, which is case-sensitive. `CLAUDE.md`'s "All 29 of them" matches; `AGENTS.md`'s "all 27," starts with a lower-case letter and is never read. A guard narrower than the shape it guards, the same family as #366.

## Acceptance criteria

Can this be done on the VM? Not applicable: both files and the check are on the host.

- [x] `tools/rules-check` matches the count in either case; run against today's `AGENTS.md` ("all 27") it FAILs with its `count` line, and that run is recorded in the day's work log with its command.
- [x] `AGENTS.md` names the right number, and `tools/rules-check` prints an `ok count` line for each of `CLAUDE.md` and `AGENTS.md`.
