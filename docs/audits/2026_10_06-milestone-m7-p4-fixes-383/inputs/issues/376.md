Source: https://github.com/pixelelated/distribution/issues/376

## Found during readiness review #375

High compatibility risk **when the approved OS rename is implemented**. This is not a failure observed on the still-ROCKNIX-named run101 image and is not the completed Blitterbot account migration.

At distro `b2378d9c33`, `cloud_scan:219` selects archives using `${label}-${osn}_SETTINGS.tar.gz`, where `osn` follows OS_NAME. Running that exact matcher over `2026_10_01-120000-GENERIC-X64-ROCKNIX_SETTINGS.tar.gz` returns the archive for ROCKNIX and no match for RASTERATOPS. Other consumers are `cloud_restore:2125,2143`, `cloud_backup:2387`, and `backuptool:143–167,1459,1463,1827`. The display rename must preserve deliberate access to legacy settings and recovery archives across these consumers.

Already written: RC2 and run101 create `*-ROCKNIX_SETTINGS.tar.gz` archives, including device-labelled cloud backups and local pre-restore snapshots. The fix must retain those bytes and their discoverability; no existing archive should be renamed or deleted merely to make the new identity work.

Related: #337, #344, #349; D-WORKFLOW-127 and D-WORKFLOW-123. Evidence and reproduction: `docs/audits/2026_10_02-milestone-375-rasteratops-0-0-1/evidence/archive-identity-probe.{sh,log}`. Audit #375 / punch list #382 is complete; this compatibility fix remains OPEN. Separate current scan/writer path mismatch: #381.
