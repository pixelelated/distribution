**Maintainer, 2026-09-29 (chat, D-QA-012), play-testing RC1 (`5b5005879e`) on the Retroid Pocket Nova:** *"another item I discovered is around the stick LED behavior. the color seems to be on by default. the second I entered the LED menu and adjusted the value, it turned off. when I tried to change the brightness, nothing happens. if I go back into "LED COLOR" and select battery (which was already selected) it turns back on. it also only seems to activate by then deselecting a choice and reselecting it. the brightness also always seems at 100%. this might be deeper issues and LED behavior optimization can wait until this RC is finished, but I do want to track these items."*

**Tracked, not worked, until RC2 is through** (the maintainer's word above; D-UI-121). What the code says today, read and not yet checked on the device:

- The LED rows are upstream's, in `GuiMenu.cpp` (SYSTEM SETTINGS): LED COLOR runs `/usr/bin/ledcontrol <color>` the moment the choice changes, LED BRIGHTNESS runs `/usr/bin/ledcontrol brightness max|mid|min` the same way, and both write `led.color` / `led.brightness` to `system.cfg`. An `OptionListComponent` fires only on a change, which is *"only seems to activate by then deselecting a choice and reselecting it"*: choosing the value that is already selected runs nothing.
- `/usr/bin/ledcontrol` hands the call to the device's quirk script, `hardware/quirks/devices/Retroid Pocket Nova/bin/ledcontrol` (45 lines): its cases are `off`, `rgb` (applies `analogsticks.led` from `system.cfg`), `battery` (restarts `batteryledstatus.service`), `poweroff`, `list`. **There is no `brightness` case**, so LED BRIGHTNESS's call falls through the `case` and does nothing -- *"when I tried to change the brightness, nothing happens"*, *"the brightness also always seems at 100%"*. Each stick has three RGB LEDs under `/sys/devices/platform/multi-led{l,r}N/leds/rgb:{l,r}N/` (`brightness`, `multi_intensity`), and `analog_sticks_ledcontrol` takes a brightness and two colours for the ANALOG STICKS LED COLOR page.
- `battery` restarts the service that colours the sticks by charge, which is why re-selecting it turns them back on; any other choice runs `rgb` with whatever `analogsticks.led` holds -- a device that never set it applies zeros, which reads as *"it turned off"*.

Can this be done on the VM? **Partly** -- the quirk script's cases and the row's argument can be run on the host against a fake `LED_PATH` (what each row writes to the six LEDs' `brightness` and `multi_intensity` files); the LEDs lighting, their default at boot and the brightness the eye sees are the Nova's (`docs/releases/device-facts.md`, a row of its own when this is worked), asked for with a yes.
