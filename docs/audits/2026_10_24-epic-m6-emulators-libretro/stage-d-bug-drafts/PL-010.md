Title: Bug: the exit hotkey's kill target for RPCS3 names `rpcs3`, a process that never runs; the binary is `rpcs3-sa`

Found by the M6 T3 lane (#650), F-24, punch item PL-010. Medium.

## Code trace

- **How it was found:** dispositioning upstream's 14 commits on the slice (Q4 (a)). `eeb33c5a37` (2026-10-05, *"emulators: fix quit hotkey targets for RPCS3, AetherSX2 and mupen64plus"*) applies to `next` cleanly and is not on it.
- **The defect at its source:** `projects/ROCKNIX/packages/virtual/emulators/sources/Start RPCS3.sh:27`, `set_kill set "-9 rpcs3"`, while line 29 starts `/usr/bin/rpcs3-sa`. The SM8550 image's install tree carries `usr/bin/rpcs3-sa` and no `rpcs3`. The exit hotkey kills the name `set_kill` registered, so it targets a name no process has.
- **The fix:** upstream's `eeb33c5a37`, `set_kill set "-9 rpcs3-sa"`, with the base merge. The AetherSX2 half goes with `c4d353449e`, which removes AetherSX2.
- **Sibling sites hunted:**
  - every `set_kill set` in the 24 `sources/*.sh`;
  - `eeb33c5a37`'s own three targets: RPCS3 here; AetherSX2, removed; mupen64plus, outside the slice.
- **The consumer, read in Phase 4.6:** `execute_kill` runs `killall ${TO_KILL}` (`system-utils/sources/scripts/input_sense:224`, T1's file), which matches by process name, not by a pattern; `rpcs3` does not match `rpcs3-sa`.
- **A sibling (Argon's G-06 lead):** `Start AetherSX2.sh` registers `aethersx2-sa` while it runs `/usr/share/aethersx2-sa/aethersx2`. `eeb33c5a37` corrects it, and `c4d353449e` removes the script; the other 16 launchers' targets match their binaries.
- **What reading cannot prove:** whether `rpcs3-sa` renames its own process to `rpcs3` (no SM8550 run with RPCS3 has been read).

Already written: nothing: `/tmp/.process-kill-data` is written per launch.

Can this be done on the VM? **No**: GENERIC_X64 carries no RPCS3. The criterion is the merged file.
