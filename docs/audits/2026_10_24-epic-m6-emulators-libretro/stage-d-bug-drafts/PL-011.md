Title: Bug: the launch table gives `psx` no default core on GENERIC_X64, and `st-v` no emulator on H700, RK3326, RK3566 and GENERIC_X64

Found by the M6 T3 lane (#650, RetroArch and the libretro cores) in its audit, F-05, punch item PL-011 (D-WORKFLOW-187: a defect the renovation finds is a bug like any other). Low.

## Code trace

- **How it was found:** the host regeneration of the launch table (`docs/audits/2026_10_24-epic-m6-emulators-libretro/tools/regen-es-systems.sh`), which is byte-identical to the GENERIC_X64, H700 and SM8550 images' `es_systems.cfg`, parsed per device. `psx` has no `default="true"` core on GENERIC_X64, and `st-v` has an empty `emulators` element on H700, RK3326, RK3566 and GENERIC_X64 (`02-forward-audit.md` § F-05).
- **The defect at its source:**
  - `projects/ROCKNIX/packages/virtual/emulators/package.mk` 1165 to 1209: the `psx` `case ${DEVICE}` has no GENERIC_X64 arm, and the two lines after it add `duckstation-sa` and `swanstation` with `false`.
  - 1395 to 1401: `add_emu_core st-v mednafen ss true` runs only on eight devices, while `add_es_system st-v` runs on all.
  - Both blocks are upstream's lines (`git diff upstream/next next` does not touch them).
- **What the interface does with them** (EmulationStation at the pin `16dbac5211`, `SystemData.cpp` 2179 to 2213):
  - with no default, `getDefaultEmulator` returns the first emulator, so `psx` on the VM launches DuckStation standalone without saying so;
  - with no emulator it returns `""`, so an `st-v` game has no command to run.
- **The fix:**
  - a GENERIC_X64 arm for `psx` with one default (`swanstation` or `beetle_psx`: the coordinator's choice);
  - `add_es_system st-v` only where a core was added. Moving it inside the `case` is the shape the other device-only systems use (`3ds`).
- **Sibling sites hunted:** every system of the five regenerated tables, checked for zero or several defaults and for an empty emulator list. Only these two have zero defaults; none has several; only `st-v` (besides `tools` and `imageviewer`, by design) has no emulator.
- **What reading cannot prove:** which `psx` core the maintainer wants as the VM's default.

Already written: nothing on devices; the table is regenerated at every image build, and a device keeps no copy of its own (`/etc/emulationstation/es_systems.cfg` is a symlink into the system partition).

Can this be done on the VM? **Yes**: the regeneration's GENERIC_X64 table, then the guest's carousel and a `psx` launch's `exec.log`.

## Acceptance criteria

- [ ] `tools/regen-es-systems.sh` over the fixed tree gives `psx` exactly one `default="true"` core in the GENERIC_X64 table, and the H700, RK3326, RK3566 and SM8550 tables are byte-unchanged except for `st-v`.
- [ ] No regenerated table of the five devices carries a system with an empty emulator list, besides `tools` and `imageviewer`.
- [ ] On a GENERIC_X64 guest built from the fix, a `psx` launch's `exec.log` names the chosen default core.
