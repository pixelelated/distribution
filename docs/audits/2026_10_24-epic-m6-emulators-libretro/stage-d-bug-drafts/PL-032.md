Title: Bug: RetroArch patch 0012 runs a shell line built from an achievement's title and description through `system()`

Found by the M6 T3 lane (#650) in Phase 4.6, following both external seats' leads on `call_achievements_hooks.sh`. Punch item PL-032. Medium, Security.

## Code trace

- **How it was found:** both seats flagged the hook script's unquoted `$*` (shellcheck SC2048). Reading what calls it led to patch 0012.
- **The defect at its source:** `retroarch/patches/0012-cheevos-cmd.patch`, in `rcheevos_award_achievement`. It formats `<cheevos_cmd> <id> "<title>" "<description>" > /dev/null 2>/dev/null` with `snprintf` and passes the line to `system()`.
  - The title and the description come from the achievement set: RetroAchievements' data, or the offline proxy's copy of it.
  - Inside double quotes the shell still expands `$( )` and backticks, and a `"` in the text ends the quoting.
  - `setsettings.sh:485` (T1's lane) sets `cheevos_cmd` to `/usr/share/libretro/call_achievements_hooks.sh` whenever RetroAchievements is on for the platform. So the line runs on every unlock, as root, on every device, whether or not an LED hook exists.
- **The hook's half:** `call_achievements_hooks.sh:15,17` passes `$*` unquoted, so a multi-word title reaches the LED script re-split. SC3014's `==` is not a defect: `/bin/sh` is bash on the image.
- **The fix:**
  - run the hook without a shell, with `fork` and `execv` and the id, title and description as three arguments (or escape each for the shell);
  - pass `"$@"` in the hook.
- **Sibling sites hunted:** the other `system()` and `popen()` calls the fork's RetroArch patches add. `grep -n -E 'system\(|popen\(' retroarch/patches/*.patch` names only this one.
- **What reading cannot prove:** the set authors' review of titles on retroachievements.org. No unlock carrying a `$( )` title has been observed; the guest proof below constructs one.
- **Upstream:** the patch is ROCKNIX's. This is a contribution candidate for #585 (D-WORKFLOW-164), held under D-WORKFLOW-165.

Already written: nothing stored. A crafted title would have run once per unlock, and there is no state to migrate.

Can this be done on the VM? **Yes.** On the guest:
- `tools/ra-ui-test`'s loopback provider serves an achievement whose title carries `$(touch /tmp/t3-hook)`;
- the achievement is awarded;
- the marker is read.

The award is a synthetic input (P-05), named as such in the tick.
