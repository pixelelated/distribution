Title: Bug: GENERIC_X64's launch table offers core choices its skip list does not build, and its id Tech scanner calls a script the image lacks

Found by the M6 T3 lane (#650) in Phase 4.6, from both external seats' G-01. Punch item PL-030. Low.

## Code trace

- **How it was found:** both seats saw that GENERIC_X64's table offers systems whose cores Q6 Table 1 shows as not built. The lane then checked every `retroarch` `<core>` of the GENERIC_X64 image's `es_systems.cfg` (`m7-signin-build-20261022-07`, BUILD_ID `069fc2704421…`) against its `usr/lib/libretro/`. Seven are missing:
  - `uae4arm` (`amigacd32`);
  - `parallel_n64` (`n64`, `n64dd`);
  - `ppsspp` (`psp`, `pspminis`);
  - `ffmpeg` (`mplayer`, PL-031's bug);
  - `idtech`, which is not a defect: the `idtech` system's games are `.sh` files, and `runemu.sh:488-492` runs a `.sh` ROM itself.
- **The defect at its source:** `virtual/emulators/package.mk` 107 to 115 drops these cores on GENERIC_X64 (`X64_SKIP_CORES`). The systems' `add_emu_core` lines still name them, as non-default choices. `runemu.sh:302` then loads `-L /tmp/cores/<core>_libretro.so`, a file that does not exist.
- **The scanner:** `Scan id Tech Games.sh` (installed on GENERIC_X64 as a TOOLS entry) runs `/usr/bin/generate-idtech.sh >/dev/null 2>&1`. That script comes with `idtech-lr`, which GENERIC_X64 skips, so the entry silently does nothing.
- **The fix:** skip those `add_emu_core` lines where the skip list drops the core, and install the scanner only beside `generate-idtech.sh`.
- **Sibling sites hunted:** the same comparison over the H700 and SM8550 images. Each misses only `pcsx_rearmed32` (#802), `ffmpeg` (PL-031) and the `.sh` system `idtech`. Argon's `nds`/`desmume` part was refuted: `desmume_libretro.so` is installed.
- **What reading cannot prove:** the launch failure's exact screen. The guest run below shows it.

Already written: nothing beyond a per-game core choice a player may have made. The game list keeps it, and it falls back to the system's default once the line is gone. Read both; nothing to migrate.

Can this be done on the VM? **Yes.** GENERIC_X64 is the VM image:
- the regeneration's table first (`tools/regen-es-systems.sh`);
- then, on the guest, one of the six choices launched, and the scanner run from TOOLS.

- [ ] The GENERIC_X64 install tree carries `usr/config/modules/Scan id Tech Games.sh` only beside `usr/bin/generate-idtech.sh`.
