Title: Bug: `Start Azahar.sh` and `Start MelonDS.sh` put their shebang on line 2

Found by the M6 T3 lane (#650), F-04, punch item PL-013. Low.

## Code trace

- **How it was found:** shellcheck v0.11.0 over the slice's shell sources: SC1128, *"The shebang must be on the first line"*, in both files (`02-forward-audit.md` § shellcheck).
- **The defect at its source:** `projects/ROCKNIX/packages/virtual/emulators/sources/Start Azahar.sh` and `Start MelonDS.sh` begin with an empty line and put `#!/bin/bash` on line 2 (`head -4 | cat -A`). Both are upstream's (`1a30c6a368`, `02fe535ab1`).
- **What happens:** the tools system starts a module as `/usr/bin/foot %ROM%`. `foot` calls `execvp`, the kernel refuses a file without a first-line shebang (ENOEXEC), and glibc falls back to `/bin/sh`. On the images `/bin` points to `/usr/bin` and `usr/bin/sh` to `bash`, so the scripts still run under bash today, and `Start MelonDS.sh`'s `[[` works. The defect rests on those two facts outside the files.
- **The fix:** delete the empty first line of each.
- **Sibling sites hunted:** all 24 `sources/*.sh` under shellcheck; these two are the only SC1128.
- **What reading cannot prove:** the fallback on an image whose `/bin/sh` is not bash.

Already written: installed copies of these modules under `/storage/.config/modules` on devices that carry them keep the old first line until the image's module is copied again; harmless while `/bin/sh` is bash.

Can this be done on the VM? **Yes** for the mechanism, through a fixture of the same shape run through `env` (which also uses `execvp`). Neither module is installed on GENERIC_X64.

## Acceptance criteria

- [ ] `shellcheck -f gcc` on both files reports no SC1128, and `head -1` of each prints `#!/bin/bash`.
