# G-01 — Low — Whole ES exit removes the Wi-Fi scan deadline owner

Frozen source: ES3178b832b8d134198b2b4eede4f725d4ed283f8c; distribution fac608ff89940ce358ea9b8a95e9a08a6fe26568. Introduced by Wi-Fi picker commit a6dbc33bb3cc7152462799354876c5bad9065894. Origin: external blind F-12(b), independently narrowed against full source. No runtime reproduction or production hang is claimed.

Trigger: a scan subprocess is blocked when the entire ES process exits, rather than merely closing the picker. GuiWifi.cpp:470–533 detaches the worker; the only strong Scan owner is the worker, and the shared UI weak registry does not provide shutdown ownership. WifiScanProcess.h:30–67 and137–178 implement the timeout, group kill and wait in that worker. The spawned child has a separate process group (118–123); no parent-death mechanism or independent watchdog is installed. ES main.cpp:1317–1370 stops watchers, hasher, scraper and SaveStateBookkeeper, but has no Wi-Fi worker cancellation/join; onExit:346–352 also lacks it. Process termination does not unwind the detached worker's Child object. A still-blocked child therefore loses the process that enforces its deadline.

Refutation: picker Back is safe and intentionally leaves a bounded read alive while ES runs. Existing installed WiFi03 receipts prove27 starts/27 ends and no remaining children for that exercised flow; they do not exercise whole-process shutdown. Normal child completion or a later SIGPIPE may end a child but does not establish the missing bound. essway.service has default cgroup cleanup, which can mitigate its systemd stop path; emustation.service:13 explicitly sets KillMode=process and Restart=always, so it does not provide a universal process-group fallback. This is a conditional lifecycle defect, not evidence of a normal scan failure or data loss. The existing broader service setting is not itself newly introduced.

Smallest correction recommendation: retain the scan worker under application lifetime ownership, cancel the active spawned group and stop subsequent saved/current reads at normal ES shutdown, and join it under a short bounded cleanup path before log teardown. Preserve prompt picker Back, data-only worker ownership and the one-pending-job reopen behavior. Do not globally change KillMode without tracing emulator ownership.

Focused proof proposal, for root allocation only: one deliberately blocked read with a recorded descendant; request normal whole-ES shutdown and verify the original exit plus absence/reaping of the exact owned group within the chosen bound. A second direct helper control can prove ordinary successful return remains unchanged; accepted UI matrices need not be repeated. No physical radio is required. Source preparation and runtime remain root-owned; auditor makes no edit outside this audit directory.

Acceptance impact: AC-070 remains PASS for the actually exercised picker-close/reopen flow. Whole-process shutdown is an explicit additional lifecycle boundary and punch item G-01; it must not be described as covered by those receipts. Severity Low because it requires an overlapping blocked read and whole-frontend exit, with no demonstrated user-data mutation or ordinary-path outage.

Additional correction constraint, independently read after source-review handoff: ES main.cpp leaves SIGTERM unhandled. Decision D-CLOUD-133 explicitly rejects routing SIGTERM through normal ES teardown because it could start post-game cloud sync during system shutdown. A normal-exit hook alone is therefore not a complete owner-death remedy. Retain that decision: a scan-local custodian must keep the bounded process-group cleanup effective even when ES is terminated, or the finding must remain open for that path. A bare external timeout is not sufficient if its leader exits while a descendant still holds the pipe. The minimal design must explain both leader and descendant custody without changing unrelated cloud/game shutdown semantics.

Historical qualification boundary independently reread after final prompt sealing: docs/qa-logs/2026-10-13-wifi-picker-source/README.md:48–56 explicitly said escaped groups, uninterruptible tasks and frontend termination still require the coordinator's outer job/guest cleanup. G-01 is newly raised as an audit punch finding, not a claim that this limitation was previously undisclosed. That preparation record is not a production owner-death mechanism. Prior Back/reopen27/27 acceptance remains valid within its stated scope. Root and source reviewer informed; sealed final prompt unchanged.
