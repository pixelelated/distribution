## § The selection

**How a quirk is selected** (T22's files, cited):
- `sysutils/autostart/profile.d/002-autostart:6-12` sets `QUIRK_DEVICE`:
  - `strings /sys/firmware/devicetree/base/model` when that file exists (`:6-8`);
  - else `strings /sys/class/dmi/id/sys_vendor` and `product_name` (`:9-10`);
  - then `/` → `-` (`:12`).
- `sysutils/autostart/sources/autostart:31-43` runs, as root and in glob order, only the files directly in `devices/${QUIRK_DEVICE}/`: `if [ -f "${script}" ]` at `:38` skips the subdirectories.
- `quirks/package.mk:15` copies every `devices/*` into every image, and `:20` runs `chmod -R 0755 ${INSTALL}/usr/lib/autostart/quirks`. That masks the 71 `100644` modes.
- The `bin/` helpers are reached through T22's wrappers. `system-utils/sources/scripts/ledcontrol:14-17` (and its three siblings) `exec`s `devices/${QUIRK_DEVICE}/bin/<name> $*` when it exists, else the platform's, **unquoted**.
- `bin/achievements` is reached through `retroarch/scripts/call_achievements_hooks.sh:14-17`.
- **A second derivation** is `rocknix-info:8-12` (T1's file): `tr -d '\0'` over the same `model`, the same DMI fallback and the same `/` → `-`. It is a lead for the coordinator (F-09).

## Findings

### F-01 (Q3; Low; a candidate bug in a fork-own file): with `led.color` never set, the Nova's battery helper lights all eight stick LEDs at every boot

- **The start.** `batteryledstatus.service` (`system-utils/system.d/batteryledstatus.service`: `ConditionPathExists=/usr/bin/battery_led_status`, `ExecStart=/usr/bin/battery_led_status`, `WantedBy=multi-user.target`) starts at every boot. The wrapper every image carries satisfies the condition, and it execs the Nova's `bin/battery_led_status`.
- **The test.** The helper's loop tests `[ ! ${BAT_LED_STATE} == "battery" ]` (`:73`), unquoted. With `led.color` unset the test is false, so the loop runs battery mode.
- **No seed.** Nothing in the tree seeds a default `led.color` (b03: the four reads outside the quirks are `led_flash:7`, `rocknix-fake-suspend:140`, `powerstate.sh:16` and a comment), so a fresh Nova has it unset.
- **The fixture** (`tools/t29-battery-unset.py`, b04): the real script, settings in a file, sysfs under a scratch root, `sleep` ending the first pass.
  - `led.color=unset`: `brightness=['255'] multi_intensity=['0 255 0'] lit=yes`.
  - `led.color=rgb`, the control: `lit=no`.
  - `led.color=battery`: `lit=yes`.
  - Upstream's RP6 copy behaves the same.
- **Why it matters.** This is the mechanism of D-UI-121's *"the default comes on"* (#332), a symptom the fork's #332 fix (`8ee3d9dfe6`) did not address.
- **The class.** The same unquoted test is in **13 files** (b02): the Nova's, ten more devices' `bin/battery_led_status` (seven of them tier B: Pocket ACE, DS, EVO, S 2K, Odin 2 Portal, Thor, RP6; the other three Pocket S2, Odin 3 and MANGMI Pocket Max), and `platforms/SM6115` and `SM8250`. **`AYN Odin 2/bin/battery_led_status:63` quotes it**, `[ ! "${BAT_LED_STATE}" == "battery" ]`, and breaks when the setting is unset.
