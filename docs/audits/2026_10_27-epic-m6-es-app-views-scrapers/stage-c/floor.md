## Defects noticed outside the 27 items

- ArcadeDBJSONScraper.cpp:56: `system && A || B || C` binds as `(system && A) || B || C`, so a null `system` is dereferenced.
- ArcadeDBJSONScraper.cpp:213-218: a `release` below 4 does not call `setError`, so a format change reads as "no match", not an error.
- ScreenScraper.cpp:384-385 with Scraper.cpp:337: "maximum threads per minute reached" returns false to ask for a retry, but the return value has been discarded since 3a997b651. The game is reported as no match.
- Scraper.cpp:372-383: these branches also apply to dependency requests (TheGamesDB `/Games/Images`). A 404 or IO error on one game's images request sets DONE without `process()`, which discards every result of the search. A 4xx/5xx fails the whole search.
- Scraper.cpp:596: a 429 retry rebuilds the request with `HttpReq(url, mSavePath)`, which drops `options.customHeaders` (the ScreenScraper `Referer`).
- Scraper.cpp:556: `maxheight` is set from `maxWidth` (both axes use the width). This may be an intentional square bound; unproved.
- Scraper.cpp:495-501: one failed media download fails the whole resolve, so the game's text metadata is discarded too. The `ResolvePair`s are deleted but left in `mFuncs`, dangling.
- HttpApi.cpp:258: the result of `writeAllText` is not checked; metadata is set and success returned even when the write failed.
- HttpServerThread.cpp:390-397: when a media file cannot be read, `GET .../media/<type>` returns 200 with an empty body instead of 404.
- ThreadedScraper.cpp:220: an erased `ScraperThread*` is never deleted (leak). ThreadedScraper.cpp:335 writes `mExitCode` from the UI thread without atomics, and `mPaused` (:181) is the same; these are data races.
- HfsDBScraper.cpp:204: `doc["token"].GetString()` is called without `IsString`/`IsObject`. :192 posts the user and password without URL-encoding them. :222 refreshes `mTokenDate` on every request, so the 30-minute local expiry (:172) never fires during a run.
- GuiScraperStart.cpp:74-78: the fallback scraper selection is not written to Settings, which is the path to the 3.15 null dereference. ScraperSearchComponent.cpp:321 also dereferences null.
- SystemView.cpp:274: the guard checks only `count >= sz`. With fewer than 10 systems, fast-forward does nothing while fast-backward moves -10 mod sz. SystemView.cpp:284: the local `mCursor` shadows the member.
- BasicGameListView.cpp:101: `recurseFind` is dead code with external linkage, superseded by `FolderData::findChildrenListToDisplayAtCursor`.
- GamesDBJSONScraper.cpp:92: `TANDY` and `TRS80_COLOR_COMPUTER` share id 4941. That this is wrong is unproved without the TheGamesDB platform list.
