## As built
- HttpText::tlsChoice: verify the peer (VERIFYHOST 2) unless allowUnverifiedPeer, and always with a client certificate. HttpText::kCaBundle, /etc/ssl/certs/ca-certificates.crt, set as CURLOPT_CAINFO where it exists and the peer is verified (not on Windows).
- HttpReqOptions::allowUnverifiedPeer, false by default. One request sets it: ImageDownloadHandle, the scrapers' media download (Scraper.cpp:550; every use listed by grep in s14-checks).
- The client-certificate path no longer sets VERIFYHOST 0.
- ImageDownloadHandle keeps the request as it was made (mRequestUrl with the size arguments, mOptions with the Referer and the opt-out), and the 429 retry makes that request again; it rebuilt from the bare URL and the save path.
- A certificate that does not verify reaches S12's REQ_CERTIFICATE_ERROR and its sentence.
- T20's HttpReqOptions::httpsRedirectsOnly (ES 5c0ddaaee) is not merged on this branch; allowUnverifiedPeer sits where it will sit beside it.

## What else S14 changes
Every other HTTPS request the interface makes -- RetroAchievements, the theme and content downloads, ScreenScraper's API -- now verifies its server against the image's bundle, as D-NET-017 decides. A server whose certificate the bundle does not cover now fails with the certificate class instead of being trusted.
