## Code trace

**Where (at `16dbac5211`):** `guis/GuiInputConfig.cpp:128-136` (`:134`)

**The defect:** For a pad, the CONFIGURING page's subtitle formats `_("GAMEPAD %i")` with `target->getDeviceId() + 1` (`:134`), upper-cased at `:136`. The SDL instance id grows with every plug-in, so a pad unplugged and plugged back in, or a third pad, reads GAMEPAD 3 or GAMEPAD 7 whatever pad is in the player's hand; the number matches nothing the player can see.

**How it was found:** T35's audit (#682): L-17, with 3.21; PL-16 in `docs/audits/2026_10_31-epic-m6-es-core-window-input/05-punch-list.md` and #1337. Ruled at the stage-D pause (ruling 14): the device's name, upper-cased by `:136`, falling back to a new msgid `GAMEPAD` with `MANETTE` in the same commit (D-UI-051).

**The positive before the fix:** Read at the pin (`:134`). The case is written first in stage E's S8: 3.21, the subtitle lifted as text, asserting the argument is the device's name; it FAILs at the pin (`getDeviceId() + 1`).

**What reading cannot prove:** how SDL names the pads players own (the name is SDL's, from the pad).

**Can this be done on the VM?** Yes -- host-only for the case; on a guest, the detect page's hold (G-08) to CONFIGURING and a frame of the subtitle in English and French.
