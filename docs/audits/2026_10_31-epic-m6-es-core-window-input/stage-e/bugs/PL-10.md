## Code trace

**Where (at `16dbac5211`):** `InputManager.cpp:792-800` (`:795`)

**The defect:** The F4 shortcut builds its quit event with `new SDL_Event()` and hands it to `SDL_PushEvent`, which copies the event into SDL's queue; the allocation is never freed. One event leaks per press.

**How it was found:** T35's audit (#682): L-24; PL-10 in `docs/audits/2026_10_31-epic-m6-es-core-window-input/05-punch-list.md` and #1337. Upstream's line, rule 6's contained fix (ruling 15).

**The positive before the fix:** Read at the pin (`:795`: `SDL_Event* quit = new SDL_Event();`, no `delete`). The case is written first in stage E's S6: the lifted `:792-800` with `SDL_Event`/`SDL_PushEvent` doubles under `-fsanitize=address`, where LeakSanitizer reports the event at the pin.

**What reading cannot prove:** nothing more: the leak is one event per press, and F4 quits.

**Can this be done on the VM?** Yes -- host-only (the S6 sanitizer program in `tools/t35-build-tests.sh`).
