## Code trace

**Where (at `16dbac5211`):** `guis/GuiTextEditPopupKeyboard.cpp:392-397` (the `x` button), `:491-496` (the CLEAR key); `guis/GuiTextEditPopup.cpp:34` (the CLEAR button)

**The defect:** On both text popups CLEAR calls `mOkCallback("")` and closes the popup, and on the keyboard the `x` button does the same. One press therefore saves an empty value into whatever the popup edits -- the cloud folder, a host name, the Wi-Fi key -- with no question and no way back. `es-ui-style-guide.md` § Confirmations asks a consequential action to ask, and `least-surprise.md` expects CLEAR in a text editor to clear the text.

**How it was found:** T35's audit (#682): L-14; PL-12 in `docs/audits/2026_10_31-epic-m6-es-core-window-input/05-punch-list.md` and #1337. Ruled at the stage-D pause (ruling 4, D-UI-136): CLEAR empties the field and keeps the popup open; OK commits, CANCEL or back discards; no question and no new sentence. The change reaches every page that uses the two popups, upstream's included, as the surface's own behaviour.

**The positive before the fix:** Read at the pin (`:394`, `:493`, `GuiTextEditPopup.cpp:34`: `okCallback("")` then `delete this`). The case is written first in stage E's S8: the lifted lines in a popup double, where CLEAR and `x` call the OK callback with an empty string at the pin. On the image the keyboard device's `s` typed into the field rather than acting as X (G-06), so the frame is owed to a pad or the CLEAR key.

**What reading cannot prove:** which settings a player has emptied this way.

**Can this be done on the VM?** Yes -- host-only for the case; on a guest, G-06's walk to the cloud folder editor with the keyboard's CLEAR key pressed, then a frame of the field.
