## Code trace

**Where (at `16dbac5211`):** `InputManager.cpp:1225`, `:1232` (`writeDeviceConfig` `:1179-1240`; the hot-plug write `:605`); `utils/AtomicFileUtil.h:30-42` (T21's `AtomicFile::writeText`)

**The defect:** `writeDeviceConfig` saves the merged document with `doc.save_file(path)` (`:1225`) and the shareable copy with `lastdoc.save_file(lastpath)` (`:1232`). pugixml's `save_file` opens the destination for writing and truncates it before the first byte, so a write cut by power loss, a full card or a killed process leaves a short `es_input.cfg`. D-CLOUD-078 asks every writer to replace the last good state only after the new one is whole; the fork's `AtomicFile::writeText` (T21's, `AtomicFileUtil.h:42`: write a temporary, fsync, rename, fsync the directory; on failure the temporary is removed and the path untouched) is the house way, and `AtomicFile::` has 0 uses among the five writes the lane counted.
