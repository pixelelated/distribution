### 3. Lifetimes and threads (§ The hasher, § The reader; L-19 to L-23)

- **Status:** *confirmed*
- **Evidence:** `ThreadedHasher.cpp:138-139, 164, 181-266, 361-393, 403-414`
- **Analysis:** L-21 is a genuine, high-severity use-after-free defect. `ThreadedHasher::ThreadedHasher` spawns worker threads inside the constructor (`:138-139`), before `new ThreadedHasher(...)` even returns to `ThreadedHasher::start` (`:375`) and before `ThreadedHasher::mInstance = hasher` is assigned (`:392`). #### R-16 — Safety of `rvz_hash.cpp` against a hostile RVZ file
- **Status:** *confirmed*
- **Evidence:** `external/libcheevos/rvz_hash.cpp:24-37, 100-129, 156-347, 374-389`
- **Analysis:** `rvz_hash.cpp` validates every offset, count, and size before allocation or indexing, using overflow-safe subtraction bounds (`offset <= fileSize && size <= fileSize - offset` at `:197, 309`; `offset < discSize && length <= discSize - offset` at `:207`; `entry.first < groups.size() && entry.count <= groups.size() - entry.first` at `:210`; `length <= result.size() - output` and `length <= packed.size() - input` at `:110, 120`). Table allocations are bounded prior to multiplication (`rawCount <= 4096` -> `rawCount * 24 <= 98304`; `groupCount <= 65536` -> `groupCount * 12 <= 786432`), single work buffers are capped at `MaxWork` (3 MiB, `:26, 309, 317`), Zstandard decompression requires an exact single-frame match (`:330-334`), and cumulative decompression and logical read bytes are capped at 512 MiB (`totalDecoded`, `:317`) and 128 MiB (`totalRead`, `:246`) respectively. In `seek()` (`:232-236`), `offset < -static_cast<int64_t>(base)` is checked before `-offset` is evaluated (with `base <= MaxDisc` = 2 GiB), preventing `INT64_MIN` negation overflow.

#### R-17 — Correctness of the RVZ padding generator and shift `{24, 18, 8, 0}` argument (L-25)
- **Status:** *confirmed*
- **Evidence:** `external/libcheevos/rvz_hash.cpp:66-98, 111-116`
- **Analysis:** In Dolphin's WIA/RVZ Lagged Fibonacci Generator, the 17-word big-endian seed is expanded to 521 words using shifts `<< 23` and `>> 9` (`rvz_hash.cpp:69-72`), after which Dolphin clears bits `16..23` of every word and replaces them with `(w >> 2) & 0x00ff0000`, and from that point on `advance()` (`:73-78`) performs only word-wise XOR (`^=`). Because selecting any fixed subset of bit positions (`shifts = {24, 18, 8, 0}` at `:87, 95`) is linear over $\mathbb{F}_2^{32}$, it commutes with every subsequent XOR in `advance()`, producing the exact same byte stream at every aligned or unaligned `offset` as applying the tweak to all 521 words before `advance()`.
