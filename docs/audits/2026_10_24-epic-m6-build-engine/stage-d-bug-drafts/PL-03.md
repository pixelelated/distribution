## Code trace

- **How it was found:** F-18 in `02-forward-audit.md`, read at `8ebaf8daad`; evidence: P13 (`tools/sb-get-git-head.sh`).
- **The defect at its source:** `scripts/get_git` accepts a cached clone whose `HEAD` is not `PKG_VERSION`. Where: `scripts/get_git:36,198`.
- **The fix's shape:** In `_repo_exists_and_valid`, compare `git rev-parse HEAD` with `git rev-parse "${PKG_VERSION}^{commit}"` (the pin may be abbreviated, `get_git` 8) instead of `git ls-remote . | grep`, and discard edits to tracked files (`git reset --hard`, since `git restore --staged .` keeps them, G-07); on a mismatch fall through to the re-clone; `popd` on every return. Re-graded High to Medium in Phase 4.6: the cache directory is keyed by the pin (`config/functions:1350`), so a pin bump gets a fresh clone.
- **Sibling sites:** named in the finding; any further site is listed here when the fix's stream brief hunts them.
- **What reading cannot prove:** what only a build shows; this issue's image proof is the coordinator's first build after the merge (`fix-pending-image`) unless the criterion below is a sandbox's.
- **Already written:** source caches under `sources/` and `/workspace/cache/rocknix-sources` may hold clones whose `HEAD` is not their recipe's pin; the fixed check finds each at the next fetch and re-clones it; images already built from a stale clone are corrected by their next build

**Can this be done on the VM?** No: a fetch on the build host; `tools/sb-get-git-head.sh` is the agent-verifiable artifact (fix-sandbox), the first build after the merge the image proof
