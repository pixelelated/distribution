# Generated build-tree custody (#493)

The retirement engine calls `compile_config(run, row, proof, inputs)` through
`runpy` when the original accepted completion proof includes
`build_tree_inputs`. This writes derived custody under the original run.
Admission, the original proof, registry, deletion journal and output files
stay under their existing owners. The tool performs no disposal or host-use
check.

## Inputs in the original accepted completion proof

`build_tree_inputs` is a JSON object with these fields.

| Field | Contents |
| --- | --- |
| `schema` | Integer `1`. |
| `roots` | One to eight explicit working output scopes. Each has an absolute `path`, the original parent host enrollment digest in `host_manifest_sha256`, and exactly one of `catalog` or `keeper`. |
| `reference_roots`, `reference_stores` | The compact reference roots selected by the owner and stores inside those roots. |
| `registry_state_roots` | The same state roots the engine verifies for the current registry route. |
| `source_evidence`, `deliverable_evidence` | Separate nonempty lists of exact `{path,sha256}` references already in the original completion proof's `evidence`. Keep source, regeneration inputs and retained deliverables outside all selected roots. |

A root is a declared `build.*` direct child of the checkout, or a directory
below its `build/` working area. Even for a whole-profile root, discovery is
limited to the working area. For a nested root, the compiled `host_scope`
binds the exact admitted `build.*` parent to its device, inode, owner and mode.
The engine validates live enrollment, registered use and current namespace
visibility before mutation.

- **Native catalog.** Supply `catalog` as an accepted `{path,sha256}`
  reference outside the selected scopes. The privately written original
  catalog has `schema: 1`, `run`, `admission_id`, `admission_sha256` from
  `RUN/admission.json`, `registry_generation` from
  `RUN/admission-input.json`, `root`, `directories` and `files`.
  Use canonical relative paths, with `.` for the root directory. Each
  directory has `{path,identity}` using device, inode, uid and mode. Each
  file has `{path,identity,sha256}` using device, inode, size, mtime_ns,
  ctime_ns, allocated_bytes, uid, links and mode. Capture the catalog before
  accepting the proof, using the producing build's actual generated-output
  list. The compiler rechecks named identities; the sealed original catalog
  supplies the generated bytes' hashes.
- **Independent keeper.** Supply `keeper: {path,identity}` with the
  retained root's device, inode, uid and mode outside the admitted product
  tree. The keeper path corresponds to the selected root. The compiler
  selects regular same-relative matches by distinct singly linked file
  identities, size, mode and streamed SHA-256. Unmatched files, links,
  nested repositories and unlisted content stay outside the selection.
  Retain the keeper for revalidation and recovery. Independent proof
  receipts include the matched keeper hashes.

A compilation pass is capped at 8,192 visited/read items, eight roots,
48 levels of working-directory depth, 16 MiB per metadata file, 8 GiB of
streamed reads and 45 seconds of checked work. The existing caller also
applies its outer deadline. A missing or changed receipt, unsafe identity
or exhausted bound holds the run.

## Invocation and recovery

Ordinary use is the existing post-consumption and scheduled engine route.
To compile custody alone for an already consumed, exact original proof:

```sh
python3 -I -B tools/host-maintenance/build-tree-custody \
  --run /absolute/checkout/.build-runs/RUN \
  --acceptance /absolute/retained/original-acceptance.json
```

The CLI prints the engine config or a held result with exit 2. The config
and its two hashed receipts are published together, without overwrite, as
`RUN/build-tree-custody/`. A retry revalidates the original run and accepted
inputs, source, delivered results and independent keepers. It reuses the
same selected names and identities after partial deletion. The retirement
engine's existing journal accounts for absent, changed and removed names.
An interrupted unpublished staging directory supplies no custody.

Run `python3 -I -B tools/host-maintenance/test-build-tree-custody` for
disposable producer, engine-interface and recovery checks.
